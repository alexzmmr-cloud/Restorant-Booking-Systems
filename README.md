# Verde Marea Booking System

Локальная система бронирования столов ресторана — гость выбирает окно и бронирует стол, администратор управляет потоком бронирований, столами и ролями. MVP без внешних интеграций и публичного деплоя.

## Основные возможности

* Регистрация и вход гостя, сессия на сервере
* Выбор даты/времени/числа гостей с показом только допустимых окон, автоматический подбор стола
* Личный кабинет гостя: список бронирований, отмена (до дедлайна 3 часа), внутренние уведомления
* Административный контур: фильтр бронирований по статусу/дате, смена статуса (подтвердить/отменить/завершить/no_show)
* Управление столами (создание, деактивация)
* Управление ролями user ↔ admin (только super_admin)
* История изменений (AuditLog) по каждому административному действию

## Стек и инструменты

* Next.js 16 (App Router, Turbopack), React 19, TypeScript
* Tailwind CSS v4, Zod
* PostgreSQL, Prisma 7 (`@prisma/adapter-pg`)
* bcryptjs, серверные сессии на HMAC-подписанной cookie

* `app/` — страницы и маршруты Next.js (гостевой контур, `admin/*`, `api/`)

* `lib/booking/` — правила доступности окон, подбор стола, создание/отмена бронирования, машина состояний
* `lib/admin/` — административные действия (бронирования, столы, роли)
* `prisma/schema.prisma`, `prisma/migrations/` — модель данных и миграции
* `prisma/seed.ts` — тестовые пользователи и столы
* `specification.md` — источник правды по сущностям, ролям, правилам
* `design.md` — источник правды по визуальным токенам
* `Plan.md` — план работ по шагам и их статус

## Запуск

Требования: Node.js 20+, локальный PostgreSQL (запущенный сервер, роль с правом создавать базу).

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Создать роль и базу PostgreSQL:
   ```bash
   psql -c "CREATE ROLE verde_marea WITH LOGIN PASSWORD 'свой-пароль';"
   psql -c "CREATE DATABASE verde_marea OWNER verde_marea;"
   ```
3. Скопировать `.env.example` в `.env` и заполнить своими значениями:
   ```bash
   cp .env.example .env
   ```
   * `DATABASE_URL` — строка подключения к базе из шага 2
   * `SESSION_SECRET` — случайная строка, например `openssl rand -base64 32`
   * `.env` не коммитится, реальные значения нигде не публикуются
4. Применить миграции и создать контрольные данные:
   ```bash
   npx prisma migrate dev
   npx prisma db seed
   ```
   `db seed` идемпотентен (upsert по email/name) — повторный запуск не плодит дубли
5. Запустить сервер разработки:
   ```bash
   npm run dev
   ```
   Приложение — [http://localhost:3000](http://localhost:3000)

### Создание пользователей других ролей

* `super_admin` появляется только через seed (`npx prisma db seed`) — интерфейс не позволяет создать или назначить эту роль
* `user` создаётся регистрацией на `/register`
* `admin` назначается вручную: войти как `super_admin` → `/admin/users` → повысить нужного `user` до `admin`

## Что важно знать при работе с проектом

* Роль проверяется на сервере при каждом чувствительном действии, не только в интерфейсе
* `passwordHash` никогда не покидает сервер в ответах API
* Правила доступности окон считаются динамически, не хранятся статичным списком
* После изменения `prisma/schema.prisma` — обязательна миграция (`npx prisma migrate dev --name <описание>`) и, при необходимости, обновление `prisma/seed.ts`
* Секреты (`DATABASE_URL`, `SESSION_SECRET`) — только в `.env`, не в `.env.example`, не в коммитах
* Нет внешних интеграций, публичного деплоя и лишнего production-контура — см. `specification.md`

## Основной сценарий проверки

1. Войти гостем → `/book` → выбрать дату/время/гостей → создать бронирование
2. `/bookings` — бронирование видно, отмена доступна (если до начала больше 3 часов)
3. `/notifications` — пришло уведомление о создании брони
4. Войти под admin → `/admin/bookings` → подтвердить/отменить/завершить бронирование, отметить no_show
5. `/admin/audit-log` — действие администратора зафиксировано
6. `/admin/tables` — создать/деактивировать стол
7. Войти под super_admin → `/admin/users` → сменить роль user ↔ admin
